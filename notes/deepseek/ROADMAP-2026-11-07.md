## 0. How to use this roadmap

1. Read sections 1-3 of this file once per session (state, recipes, delegation).
2. Take the next task in section 4 that is not DONE, whose dependencies are DONE, and that does not
   need the user. Read **only that card**.
3. Tag `[LEAD]` = do it yourself. `[AGENT:role]` = copy the card into an agent brief (section 3.2) and
   dispatch it. `[USER]` = needs the user's presence or OK: put the question on the list in section 12
   and go on with another task.
4. **Never trust an agent's summary**: run the card's "Done when" commands yourself.
5. Update `ROADMAP-STATUS.md` (one line), add the NOTES.md entry (section 2.6), commit.
6. Next task. One push per finished batch (section 2.2), never one per patch.

Labels used everywhere: **[O]** observed in our logs or code; **[R]** reported by another project
(not tested here); **[G]** guess. Effort: S (< 1 h), M (a few hours), L (days). Risk: low / med / high.

## 1. State of the world (2026-11-07)

### 1.1 Facts

- Goal: Apple's iOS 16.7.16 (iPhone X userland) on the Redmi Note 10 Pro "sweet" (SM7150, Adreno 618,
  panel 1080x2400) on a patched xnu-8796, with a **smooth home screen**, then Wi-Fi, battery, wallpaper.
  This is **not a daily-use project** (user, 2026-11-06): improvements become the new default in a
  numbered patch; a boot-arg gate is only for really experimental paths. Work is for the community.
- Repo `ios-sweet/` branch `gpu`, remote `mine` = `limonetexd/ios-sweet-gpu` (push `git push mine gpu:main`).
  `xnu/patches/` = 0001..0131 + **0138** (native-resolution default, written 2026-11-07, committed
  locally, **not pushed, never built by CI**). Next free patch number: **0139**.
- Pending drafts in `xnu/patches-pending/` (CI does not apply them): `0124` GPU window 512 MiB;
  Wi-Fi `0130..0137`; `0098`, `0100` row alignment/guard rows; `0144..0146` original beam drafts
  (superseded by 0125-0127: leave them); `0104`, `0105` the failed "super" kernel (do not use).
- Phone: `userdata` holds the gpu2 root (`ipsw/ios16-root-gpu2.simg`, flashed 2026-11-06). It is in
  fastboot unless the user is using it. OrangeFox recovery works and is **not** offset (an earlier
  note saying so was a hallucination and was removed). Known benign boot crash: `driverkitd` sig 9.
- Last CI-built kernel: **0131** (run 42314190705). Images (in `shim/out/`, not in git): `0131r`
  (ADT 750x1624, reboot after 420 s + synthetic swipes), `0131s0` (daily), and the old
  `0123s0` (1125x2436, bind default: **the known-good fallback**). SHA-256 values are in NOTES.md.
- CPU clocks are raised by the shim through the OSM LUT: gold index 10 = 1939.2 MHz, silver index 8 =
  1708.8 MHz. The LUT goes up to gold 13 = 2304 MHz and silver 9 = 1804.8 MHz [O]. See A6.
- **Display modes.** The panel is 1080x2400. The root was made for the iPhone X: 1125x2436 @3x.
  *Native* (default since 0138): the kernel reports 1125x2436 and shows the centred 1080x2400. *Scaled*
  (0129, experimental, `SWEET_SCALE=2` when building the image): 750x1624 @2x frames, cropped 720x1600
  and scaled 1.5x to the panel; faster but **its UI layout has never been checked on the screen**
  (status bar, MobileGestalt of the root are for @3x). The kernel now follows the ADT
  (`/arm-io/disp0` canvas-width/height from `tools/mkadt.py`), so kernel and ADT cannot disagree.

### 1.3 What works / what does not

- Works [O]: boots to the home screen; touch; side/volume keys; GPU compositing with Mesa freedreno in
  backboardd; real battery percentage (PM6150, default since 0106); the widget-picker freeze is gone
  (0122 keeps the GPU range pool inside the ADT carve-out); display off/on fade (IOMFB selector 12).
- Does not work / unknown: wallpaper (`PosterBoard` sig 5 every boot), `assetsd` sig 6, widget gallery
  only partly; the App Library blur freeze (backboardd userland hang, GPU idle, 2026-11-06) is not
  re-tested; Settings (`Preferences`) segfaulted 3 times in `logs/xnu-0122b.txt` [O]; "sudden stops"
  reported by the user (cause unknown); Wi-Fi only exists on another branch's kernel; no Bluetooth,
  audio, camera, cellular, sensors, haptics. Sleep is only a display fade (PSCI SYSTEM_SUSPEND unsupported).

### 1.4 Decisions already taken (do not re-litigate)

- Native 1125x2436 is the default; the 750 path stays an opt-in experiment until A9 decides with screenshots.
- Kernel changes = one new numbered patch in `xnu/patches/`; never rewrite a patch CI has built;
  small separate patches; never copy whole files of core drivers from another branch (that broke 0104).
- One push per batch; a push starts CI by itself; never also `gh workflow run` (the two runs cancel each other).
- Root goes in the existing `userdata` partition; boot only through `fastboot boot` (nothing flashed to `boot`).
- Wi-Fi comes from the DC28088 branch as **small separate patches** (PMEM/SMMU/RPMh first, then wland).
- Do not change tool/dependency versions (Mesa 25.0.7, xnu-8796, pinned commits, OrangeFox R12.0_2).
- GPU facts that must not be "fixed back": SMMU SMRs only with the exact DT stream ids and mask 0 (GMU 5,
  GPU 0); GMU HFI perf table is in kHz; `gfx.lvl` RPMh address `0x30050`; BCM vote field is 14 bits;
  GPU buffers are cached memory with manual `dc civac`; XNU's I/O map space is tiny (small `ml_io_map` windows).

### 1.5 Do-not-retry list (measured, negative)

`glblit=0` (freezes after ~7 frames) | `ca_vbl=1` (no gain, 0103 worse) | `sweetfb_threads=6` (no gain) |
`sweetfb_rate=120` (worse: 25.4 vs 26.0) | present on its own thread or at SwapEnd [R] | page flip with
flush mask `0x20041` (flicker, DC28088 0181) [R] | forced write-back for GPU buffers `sweetgpuwb=1` [R] |
cacheable SMMU walk [R] | DDR vote while presenting [R] | raising the GPU clock when pacing-limited [R] |
a kernel surface-id pool (expected gain 0-2.5 ms, high risk, `reports/research-2026-11-06-fps-next.md`).

### 1.6 Where the frame time goes (the reason for A5, B1)

[O] CoreAnimation renders every frame into a **brand-new framebuffer IOSurface** (1125x2436 = 11-14 MB;
in `logs/xnu-0122b.txt` each swap names a new surface id). Per frame: allocate (0120 recycles the memory
but zeroes it, then the first submit cleans the whole 13.9 MB out of the CPU cache), eagl attach 3.5 ms,
GL ~10 ms (of which `glFlush`/submit 4.7 ms), present copy 3.4 ms (5.9 ms scaled), delete. Why CA does not
reuse surfaces is **unknown** (B1). The eagl "big/little core" counts are meaningless on this kernel
(`TPIDR_EL0 & 0xff` is a topaz convention).

### 1.7 Stale documents (do not trust; fix when you touch them)

`README.md` "What works" table and `xnu/README.md` (upstream, CPU-only state); `tools/validate-repo.py`
(expects gapless patch numbers); `CLAUDE.md` section 5/10 had 0104/0105 and "phone state unknown"
(fixed 2026-11-07). `HANDOFF.md` and `NOTES.md` are authoritative.

### 2.1 Make a kernel patch (the only way)

```bash
# [WSL]
tools/xnu-tree.sh update            # ~/cxnu = clean xnu-8796 + every patch (first run clones xnu, ~2 min)
# ... edit files under ~/cxnu (one concern per patch) ...
git -C ~/cxnu diff --stat           # only the files you meant
printf 'short subject\n\nWhat / why / which log line proves it.\n' > /tmp/msg.txt
tools/xnu-mkpatch.sh 0139-sweet-short-name /tmp/msg.txt
git add xnu/patches/0139-*.patch && git commit -m "xnu 0139: short subject"
```
`xnu-mkpatch.sh` writes the patch with `git diff` (right hunks), runs `tools/check-patch.py`
(odd quotes = a literal newline inside a string, which broke CI three times; CR; hunk counts; lines the
ring would cut), re-applies the patch to the tree *without* your edits, and commits it in the tree.
`PENDING=1` writes to `xnu/patches-pending/`. **Nothing here compiles XNU**: only CI does, so
read your diff for undeclared names, missing includes and locking mistakes (checklist 3.3).
Two agents never share a tree: `cp -a ~/cxnu ~/cxnu-NAME` and `XNU_TREE=$HOME/cxnu-NAME ...`;
the lead gives each agent its patch number. **Patches that touch the same file are made one after the other**: the
second agent's tree must already contain the first patch (commit it to `xnu/patches/`, then `tools/xnu-tree.sh update` in
that tree), otherwise the second patch is generated against stale context and fails to apply in CI.

### 2.2 Push, CI, download

```bash
git push mine gpu:main              # starts xnu.yml by itself, but only if xnu/patches/** changed
gh run list -R limonetexd/ios-sweet-gpu -L 3
gh run watch RUN_ID -R limonetexd/ios-sweet-gpu --exit-status
gh run view  RUN_ID -R limonetexd/ios-sweet-gpu --log-failed | grep ': error:' | head -20
gh run view  RUN_ID -R limonetexd/ios-sweet-gpu --log | grep -c 'Skipping patch'     # must be 0
gh run download RUN_ID -R limonetexd/ios-sweet-gpu -n xnu-kernel -D xnu/out-0143      # last patch number
```
Never push local `main` (it has the user's real e-mail). A second push while a run is going cancels
it. Docs-only pushes start nothing. A push that changes `userland/**` starts the *userland* CI
(`userland.yml`, Mesa/EAGL, artifact `gpu-userland`) by itself; that is B6's route, so keep userland and kernel
changes in separate pushes unless you want both builds.

### 2.3 Build a boot image

```bash
# [WSL]  daily-like probe: returns to fastboot by itself after 420 s and swipes the screen every 60 s
SWEETFB_HZ=60 tools/sweet-gpu-image.sh xnu/out-0143 0143r "sweetgpu_reboot=420 sweetgpu_swipe=60"
sha256sum shim/out/shim-boot-0143r.img
SWEET_SCALE=2 SWEETFB_HZ=60 tools/sweet-gpu-image.sh xnu/out-0143 0143r2 "sweetgpu_reboot=420 sweetgpu_swipe=60"   # 750 ADT
```
Tag letters: `r` probe with reboot/swipes, `s0` daily (`serial=0`, no auto reboot), suffix `2` = scaled ADT.
First boot after a root flash needs `sweetgpu_reboot=1820` or more (datamigrator, 15-30 min).

### 2.4 Unattended test

```powershell
# [PS]  phone in fastboot, user not using it. ~10 minutes. Nothing is flashed.
.\tools\sweet-probe-loop.ps1 -Image shim\out\shim-boot-0143r.img -Out logs\xnu-0143r.txt -ProbeSeconds 540 -Xnu
```
It boots the image, waits for the kernel's timed reboot to fastboot, boots OrangeFox temporarily, reads
the console ring over adb, returns to fastboot. If it hangs at "Sending", the Xiaomi ABL is stuck: ask
the user for Power+Vol-. Pull a ring by hand: `.\tools\sweet-pull-ring.ps1 -BootRecovery -Out logs\X.txt`.
Do not start a boot while the user is using the phone.

### 2.7 Before every push (checklist)

- `python3 -I tools/check-patch.py xnu/patches/NNNN-*.patch` -> `ok` for every new patch.
- `tools/xnu-tree.sh status` -> no `NOT IN THE TREE` line (every patch applies).
- Boot-arg gates are OFF unless the card says "default on"; every new IOLog line is < 200 characters.
- The commit message says which log line proves the patch.
- Push once. Then `gh run watch`, and grep the CI log for `Skipping patch` (must be 0).

### 2.8 A/B rule for a performance change

Same image except one variable, same `-ProbeSeconds`, same swipes. Read `tools/sweet-fps-summary.py`.
Accept as the new default when **swaps/s avg >= +5 %** or **p90 >= +5 swaps**, with no new freeze,
crash or panic line and no visible corruption. Differences under 10 % need a second run. Otherwise
revert the default and record it under "negative results" in NOTES.md and in 1.5 of this file.

### 2.9 Stop and ask the user

Anything that writes to the phone (`fastboot flash/erase`, adb writes, partition writes from recovery),
downloading a binary (e.g. the `ipsw` tool), installing packages or drivers, touching
boot/recovery/modem/persist/dtbo/vbmeta, a boot while the user is using the phone, a push of local `main`,
deleting files or history. A `userdata` flash erases iOS: ask every time ("sí, flashea" was the user's wording).

### 3.3 Reviewer checklist (the lead runs it on every agent patch)

1. `git -C <tree> diff --stat`: only the expected files; no whole-file copies; no unrelated reformatting.
2. `python3 -I tools/check-patch.py PATCH` -> ok.
3. Every function, variable, macro and include used in the diff is declared in that translation unit
   *before* its use (`grep -n NAME file`), extern "C" where the callee is C. CI is the only compiler.
4. Locking: no sleeping call under a spinlock/`gpuLock`; no `IOSleep` on the presenter or vsync path;
   no unbounded loop; no allocation in interrupt context.
5. New behaviour that can hurt (clocks, memory, display, SMMU) is behind a boot-arg that defaults OFF,
   unless the card says "default on"; a kill switch exists for default-on changes.
6. New IOLog lines exist, are < 200 characters, start with a stable prefix (`SWEET XXXX:`) and say how
   to tell success from failure.
7. The commit message names the log line that proves it.

### A1: 0139 fix the RedwoodGPU statistics line `[AGENT:patch-writer]` S / low

**Why.** The line "the GPU worked N us on each of M" is divided twice (N is wrong) and the second IOLog is cut at
256 characters, so the log hides what we need to judge the cache cleaning (A5).
**Where.** `iokit/Kernel/arm/RedwoodGPU.cpp`, `RedwoodGPUUserClient::submit`, the block starting
`if (nanos >= 5 * NSEC_PER_SEC)` (grep `the GPU worked`). `redwood_gpu_worked()` in `SweetAdreno.cpp`
already returns the AVERAGE microseconds in its first argument (`worked_us / worked_n`); the IOLog prints
`timed ? worked / timed : 0` and `worked / 1000` ("ms in all"): both wrong.
**Steps.**
1. Print `worked` as the average; total ms = `worked * timed / 1000`.
2. Split the long IOLog in three, each < 200 characters: (a) submissions, command buffers, buffers named, KB out
   of the cache, us per submission, whole cleans; (b) GPU time average, count, the 7 histogram buckets;
   (c) waits, over, IOSurfaces taken as buffers, buffers, MB.
3. Count first-time whole cleans: in `toMemoryWritten()` when `!*whole` at entry, add 1 to a new
   `gGPUStat.wholeCleans` and `b->size` to `gGPUStat.wholeBytes` (add the fields to the `gGPUStat` struct; it is
   zeroed by the existing `bzero(&gGPUStat, ...)`). Print them in (a) as "N first cleans of M MB".
**Done when.** `tools/xnu-mkpatch.sh` ends with `apply check ok`; `grep -n "worked / timed" ~/cxnu/iokit/Kernel/arm/RedwoodGPU.cpp`
prints nothing; `check-patch.py` prints `ok`.
**Proof in the next run.** Three `RedwoodGPU:` lines per 5 s and a GPU time of hundreds of us to a few ms (the
old line said 5 us).

### A3: 0141 `sweetshot`, kernel screenshots into the log `[LEAD or AGENT:patch-writer]` M / low

**Why.** There is no way to see the screen during an unattended run; the 750 layout was never seen. The panel
memory is readable by the kernel, so the kernel can put a small picture into the log ring.
**Design (decided).**
- Boot-args: `sweetshot=N` seconds between shots (0 = off, default 0), `sweetshot_max` (default 8 per boot),
  `sweetshot_div` (default 6: the 1080x2400 panel point-sampled to 180x400). Triggers that are always on,
  rate-limited by `sweetshot_max`: the freeze probe (`sweet_fb_shot_request("freeze")` next to
  `sweet_freeze_dump(why)` in `AppleCLCD::statsReport`), and **Vol+ and Vol- held together**
  (`SweetHIDButtons::key` in `iokit/Kernel/arm/hid/SweetHID.cpp`, keep two booleans; usages
  `kHIDUsage_Csmr_VolumeIncrement/Decrement`; call an `extern "C"` function exported by `SweetFramebuffer.cpp`).
- A kernel thread in `SweetFramebuffer.cpp` (same start pattern as `statsMain`) wakes every 250 ms, checks the
  timer and a request flag, and skips when `fPowerOff` or `fPixels == 0`. It never takes `fLock`, never blocks
  the presenter, runs at low priority.
- Sampling: `fPixels` (kernel mapping of the panel memory), `fRowBytes`, 4 bytes a pixel in memory order
  B,G,R,A. Read every `div`-th pixel of every `div`-th row, convert to RGB565 (u16), PackBits-compress over
  **16-bit words**: control byte c in 0..127 = copy c+1 literal words; c in 129..255 = repeat the next word
  257-c times; 128 = no-op. FNV-1a 32-bit over the raw RGB565 bytes before compression.
- Output through `IOLog`, lines < 180 characters, base64 (write a 15-line encoder; no library dependency):
  `SWEET SHOT n begin WxH rgb565 packbits LEN sum HEX why TEXT t MS` / `SWEET SHOT n SEQ4 BASE64(<=100 chars)` /
  `SWEET SHOT n end`. Call `IOSleep(1)` every 32 lines so the 4 MiB ring and the UFS flush keep up. A shot is
  about 40-80 KB of text; 8 shots fit.
**Steps.** Implement in the order: encoder helpers (static, testable), the thread and request function, the
two triggers, the boot-arg parsing. Log once at start: `SWEET SHOT: every N s, max M, div D, panel WxH`.
**Done when.** mkpatch ok; read your diff against checklist 3.3 (in particular: nothing under `fLock`, loops
bounded by W*H, buffers allocated with `IOMallocData` and freed).
**Proof in the next run.** `SWEET SHOT 1 begin ...` lines and `tools/sweet-shot.py` (A4) writes a PNG that
shows the home screen.

### A4: `tools/sweet-shot.py`, the decoder `[AGENT:tool-writer]` S / none

**Spec.** `tools/sweet-shot.py LOG [--out DIR] [--scale 3] [--selftest]`. Pure Python 3 (struct, zlib, base64,
re), no PIL. The ring interleaves threads, so `SWEET SHOT` fragments can sit in the middle of other lines:
find them with a regex search, not a line-start match. Group by shot number, order chunks by SEQ4, join the
base64, decode, PackBits-decode **16-bit words** (format in A3), check the FNV-1a checksum (warn but still
write the image when it differs; report missing chunks as black rows), convert RGB565 to RGB888, write
`DIR/shot-N-why.png` (optionally nearest-neighbour upscaled by `--scale`). `--selftest` builds a synthetic
image, encodes it exactly as the kernel does (Python version of the encoder), decodes it and compares.
**Done when.** `wsl -e python3 -I tools/sweet-shot.py --selftest` prints `selftest ok`.

### A5: 0142 clean recycled surface memory in the background `[LEAD]` M / med

**Why.** [O] Every new framebuffer surface gets a whole 13.9 MB clean out of the CPU cache at its first submit
(`toMemoryWritten`, per-surface `cleanOnce`): 6189 KB / 678 us per submission on the native baseline. 0120
already recycles the memory and zeroes it in a thread call (`sweet_surf_clear_kept`) with plain `bzero`, but
nothing cleans the cache afterwards, so the render thread pays the clean.
**Design.**
1. In `iokit/Kernel/arm/SweetSurface.cpp`, `sweet_surf_clear_kept()` (the thread call): after the `bzero`,
   `redwood_gpu_to_memory(va, size)` (extern "C", `SweetAdreno.cpp`; do `dc civac` + `dsb`) over the whole
   piece, then for every page `pmap_clear_modify(pn)` (same page loop and externs as `toMemoryWritten`:
   `getPhysicalSegment`, `pmap_valid_page`). Mark the kept piece `clean = true`.
2. `sweet_surf_memory()` tells its caller whether the piece it returned is clean (an out parameter or a
   static); in the create path, `s->cleanOnce = clean` right after `s->memory = mem`. Then the first submit
   pushes only pages the CPU modified since (`pmap_is_modified`), as for any later submit.
3. A piece that was **not** zeroed/cleaned yet (the 40 ms delay has not elapsed, or the creator zeroed it
   itself) stays `clean = false` and keeps today's behaviour.
4. Kill switch: boot-arg `sweet_surfclean=0` restores today's behaviour; default on.
**Done when.** mkpatch ok; checklist 3.3 (declare the externs; the thread call must not sleep under a lock).
**Proof / A/B (A7).** `RedwoodGPU:` line (a) (A1): KB out of the cache per submission and us per submission fall
(native: from ~6000 KB / 680 us toward < 1500 KB / < 250 us), "first cleans" count falls, no corruption on the
screenshots, no new freeze. Rule 2.8.

### A6: CPU clocks to the top of the LUT, with a thermal log `[AGENT:patch-writer] + [LEAD]` M / med

**Why.** [O] The OSM LUT has more entries than we use (gold up to 2304 MHz, silver up to 1804.8 MHz);
`shim/gpuprobe.c` `cpu_boost()` writes `CPUFREQ0 + 0x920` (silver) = 8 and `CPUFREQ1 + 0x920` (gold) = 10. [R]
sailfish measured 79 C at 1824/1478 MHz, so heat is real: measure before making it default.
**Part 1 (LEAD, shim).** In `cpu_boost()` add a compile-time branch: with `-DSHIM_CPUMAX`, silver = 9 and
gold = 13 (try 12 = 2208 MHz as an intermediate build if 13 is unstable); log the states read back as today.
`tools/sweet-gpu-image.sh`: env `SWEET_CPUMAX=1` adds `-DSHIM_CPUMAX` to `SHIM_CFLAGS`
(`SHIM_CFLAGS="-DSHIM_GPUPROBE -DSHIM_GPUBOOT $([ "${SWEET_CPUMAX:-0}" = 1 ] && echo -DSHIM_CPUMAX)"`).
**Part 2 (0143, AGENT:patch-writer).** A read-only temperature line `SWEET THERM: ...` every 5 s from the stats
thread. [R] ios-flame (same SM7150 family), its patch `0255`: tsens0 TM block `0x0c263000` (sensor 0 aoss, 1-6
A55, 7-8 cpuss, 9-10 gold CPU6, 11-12 gold CPU7, 13-14 gpu), tsens1 TM block `0x0c265000` (1 wlan, 3 ddr, 5
camera); a sensor status word has bit 21 = valid and the low 12 bits = deci-degrees C. **Re-derive the
addresses and the per-sensor register offset from sweet's own device tree** (`dtb/`, the LineageOS boot.img
DTB) and from that patch (`gh api` read-only) before using them. Map with a small `ml_io_map` window (XNU's
I/O map space is tiny), read-only; if the map fails, log once and stop. Print max CPU, GPU and DDR temperatures.
**Done when.** Part 1: both images build (`shim/out/shim-boot-*.img` exist). Part 2: mkpatch ok; checklist 3.3.
**Decision.** After A7: keep max clocks as the default only if swaps/s improves by rule 2.8 AND the hottest
sensor stays below 80 C over the whole 540 s run (and in B12's 60 minutes). Otherwise keep today's clocks.
